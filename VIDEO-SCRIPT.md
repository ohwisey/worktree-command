# 2-minute video script

Plain talking, no hype. Times are rough.

## 0:00 to 0:20 the problem

"You know that feeling when one Claude Code window is grinding through a long task and you are just sitting there waiting? That is dead time. I made two one-word commands that turn that wait into a second window of real work. And they fix the one thing people always mix up: starting work connected to your current project, versus starting a brand new separate one."

## 0:20 to 0:50 the analogy

"Here is the whole idea. A worktree is a second desk for the same notebook. Same project, just a second place to work so I do not disturb the first thing. A new project is a blank new notebook. Its own git, not connected to anything."

## 0:50 to 1:30 the two commands, on screen

Show typing each one.

"`/worktree NAME` makes a connected copy of the project I am in. New branch, new folder, same project. Watch this: I type it, and a new window just opens, ready to work. So while my first window is busy, I am already going in the second one."

"`/newproject NAME` makes a brand new separate project with its own git. Same deal, a new window opens for me automatically."

## 1:30 to 1:50 the thing people get wrong

"Here is the part people get confused by. A worktree is ALWAYS a copy of the project you run it in. It does not matter where you put the folder, it is still the same project. Only a new project with git init is truly separate."

## 1:50 to 2:00 the one rule and cleanup

"One rule: one folder, one window, one branch. Never open the same folder in two windows. And when these pile up, just type `/cleanup`. It shows your worktrees and clears out the ones you are done with, and it never touches your main project. Link to install is below."
